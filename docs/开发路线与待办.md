# 开发路线与待办

更新日期：2026 年 11 月 16 日。

本文用于跟踪已讨论范围的实施进度。复选框默认未完成，不表示已经开发或验证；任务优先级和排期在试点样本确认后细化。

2026 年 11 月 23 日增量：已实现从实际反馈主动生成新增／修订案例草稿、人工校正与审核发布、来源和修改历史追溯、重复请求保护及版本冲突恢复，操作见 [反馈案例草稿](反馈案例草稿.md)。这不代表一期其他未验收项已完成，原复选框仍需按完整职责逐项复核。

## 启动准备

- [ ] 确定一个高频、处理结论相对明确的试点业务。
- [ ] 确定试用人员、问题处理人和知识维护人。
- [ ] 填写试点信息模板，提供至少一个真实完整案例，逐步补充 3–5 个不同样本。
- [ ] 确认现有技术栈、登录体系、模型服务和部署环境。
- [ ] 根据真实材料确定页面原型、案例字段和接口输入输出。

## 第一期：案例库与辅助问答

### 业务能力

- [ ] 团队登录、业务范围和基础角色权限。
- [ ] 文字与截图录入，原始材料可保存和查看。
- [ ] AI 提取现象、背景、排查过程、结论及缺失信息。
- [ ] 草稿校正、处理结果确认和案例发布。
- [ ] 案例搜索、条件筛选、来源引用和辅助分析。
- [ ] 用户补充信息和处理结果反馈。
- [ ] 案例修订、重复项处理及失效管理。

### 为第三期落实的基础

- [ ] 将检索、来源读取、草稿保存等业务动作独立封装并提供接口。
- [ ] 问题、案例、来源、草稿和运行记录采用稳定编号关联。
- [ ] 分别保存原始依据、适用条件、验证结果和修改版本。
- [ ] 收录、分析、追问规则独立维护并保存版本。
- [ ] 后台校验权限、输出结构、发布条件和状态转换。
- [ ] 写入请求支持幂等处理，重复请求不会产生重复草稿。
- [ ] 记录检索候选、引用、人工修正、耗时和调用成本。
- [ ] 建立固定评估样本，覆盖已知答案、适用条件不同和资料不足的情况。

### 验收

- [ ] 一条真实经验可以完成收录、确认、发布，再被后续问题检索和引用。
- [ ] 脱离网页，使用相同身份调用接口，可以完成关键业务操作。
- [ ] 草稿和答案能追溯到实际输入、来源版本和规则版本。
- [ ] 方案缺乏验证或背景不足时，系统保留不确定状态并提示补充信息。
- [ ] 无权访问、失效或归档材料不会作为有效方案推荐。
- [ ] 使用固定样本评估检索和回答效果，保存失败样本。

## 第二期：微信辅助收集

### 一键收集

- [ ] 确认目标电脑与微信客户端版本。
- [ ] 在一个业务群验证聊天文件转交或其他可用采集路线。
- [ ] 保留消息时间、发送人、顺序、附件及原始来源关系。
- [ ] 采集材料通过接口进入第一期既有的整理和确认流程。
- [ ] 支持批次记录、重复导入检查和失败重试。

### 定时采集可行性验证

- [ ] 验证指定群可读取的消息范围、完整性和客户端适配情况。
- [ ] 确认本地任务运行条件与凭证访问范围。
- [ ] 记录采集进度、覆盖时间、读取和导入条数、缺失及失败原因。
- [ ] 验证中断恢复、重叠窗口采集和消息去重。
- [ ] 人工对照实际聊天，核对上下文和附件完整性，再决定是否扩大到多群。

## 第三期：业务排查 Agent

- [ ] 用前两期真实任务确认动态追问、跨工具查询的实际需求。
- [ ] 为已有业务接口适配工具描述与输入输出约束。
- [ ] 根据业务需要接入只读查询工具。
- [ ] 使用 LangGraph 或经验证的替代运行时实现多步编排。
- [ ] 持久化任务状态，支持等待补充信息后继续。
- [ ] 设置步骤、时间、费用上限，支持取消与失败停止。
- [ ] 保留工具调用记录，并沿用现有权限、验证和草稿发布流程。
- [ ] 用相同数据、权限与评分标准比较固定流程和 Agent 的效果。
- [ ] 小范围验证后决定扩展范围；涉及业务写操作时另行设计执行条件。

## 排期原则

先用样本明确数据和流程，再估算开发工期。前两期的接口、数据、规则和评估基础纳入当期工作量；第三期需要的工具适配、状态管理和效果验证单独估算。
